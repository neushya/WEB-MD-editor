## 1. 기능 추가: 파일 비교(Diff)

### 요구사항
- GNB "파일 비교" 메뉴 선택 → 메인 영역이 A|B 분할 화면으로 전환.
- 각 영역 센터의 "파일 추가" 버튼으로 파일 선택 → 내용 표시.
- A|B 가운데 "비교" 버튼 → 두 파일의 차이를 IDE 스타일 diff로 표시.

### 설계 결정 (사용자 승인)
- **별도 모드(compare-mode)** 로 구현 — compare-tab 아님. App에 `isCompareOpen` 상태, 메인 영역에서 탭 내용보다 우선 렌더.
  - 이점: Tab 모델 무오염, 저장/자동저장 가드 9곳 미변경, IndexedDB 영속성 불필요, MobileLayout 무영향.
- **PC 전용** (GNB 기반이라 모바일 자연 제외, 폴더 기능과 동일 일관성).
- **텍스트 전용** 입력(PDF/바이너리 거부).
- diff는 "비교" 버튼 클릭 시 표시(2단계: 비교 전 파일 표시 → 비교 후 diff).

### 구현
- 신규 `src/components/CompareView.tsx`, `src/App.tsx`(상태+렌더 분기), `src/components/GNB.tsx`(파일 메뉴 "파일 비교" 항목).
- 의존성 `@codemirror/merge` 추가.

## 2. 결함 수정 ①: 비교 후 A|B 스크롤 불가

- **원인:** 초기 구현은 `@codemirror/merge`의 MergeView 사용. MergeView baseTheme가 내부 에디터를 `height:auto !important; overflowY:visible !important`로 강제(외부 컨테이너가 스크롤하는 설계)인데, 주입 CSS가 `.cm-mergeView` 등에 `height:100%`를 강제해 내용이 잘려 스크롤 불가. 추가로 flex `min-height:auto` 함정.
- **수정:** 높이 강제 제거 + 스크롤 컨테이너에 `min-h-0` 추가(+ 비교 전 패널도 동일). 무효한 baseLayouttheme 제거.
- **검증:** 컨테이너 clientHeight 472 vs scrollHeight 2191 → 스크롤 생성, 실제 스크롤 동작 실측.

## 3. 결함 검토 ②: 동기 스크롤 vs 개별 스크롤

- 1차 보고: MergeView는 정렬 유지를 위해 **단일 동기 스크롤**이 설계이며 표준 IDE diff와 동일 → 동기 유지 권장으로 합의.
- 재요청: 사용자가 "각 영역 개별 스크롤"을 명확히 재확인(다른 도구는 따로 스크롤됨) → **개별 스크롤로 방향 전환.**

---

## 4. 결함 수정 ②→ 옵션 C: 개별 스크롤 (MergeView 폐기, 커스텀 2-에디터)

- **원인:** MergeView는 구조적으로 단일 스크롤 영역(`.cm-mergeView` overflowY:auto) + 정렬 spacer 삽입 → 개별 스크롤 미지원. CSS 강제(옵션 B)는 spacer 빈공백 글리치로 품질 부적합.
- **수정:** MergeView 폐기, 독립 스크롤 2-에디터 직접 구성.
  - diff 계산: `Chunk.build(Text, Text)` (MergeView 없이 export됨).
  - 줄 하이라이트: chunk가 걸친 줄을 `Decoration.line`으로 표시(A: `cmp-del` 빨강, B: `cmp-add` 초록), `StateField`로 정적 주입.
  - 각 패널이 자체 `.cm-scroller`(height 100% + overflow auto)로 **완전 독립 스크롤**.
  - 읽기 전용, isDarkMode 변경 시 재생성.
  - `@codemirror/merge`는 `Chunk` 계산용으로만 계속 사용(MergeView 미사용).
- **트레이드오프(승인):** 개별 스크롤 특성상 두 패널 간 줄 정렬·연결선 없음. 단어 단위 하이라이트는 미포함(줄 단위).
- **검증(브라우저 실측):** A를 800px 스크롤 시 A.scrollTop=800 / B.scrollTop=0 → 독립 스크롤 확정. 변경 줄 A 빨강·B 초록 하이라이트 정상. 빌드 통과, 콘솔 에러 0.
