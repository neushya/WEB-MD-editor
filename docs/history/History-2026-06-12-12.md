## 2. 기능 배포: PC 탭바 overflow 드롭다운 (재구현분)

- **배경:** Part 11에서 revert됐던 기능을 `position: fixed` 방식으로 재구현한 로컬 작업분을 정식 배포.
- **구현 핵심 (`src/components/TabBar.tsx`):**
  - 기존 `overflow-x-auto`(가로 스크롤) → `overflow-hidden` + DOM 위치 기반 overflow 감지로 전환.
  - 감지 로직(`recalcOverflow`): `tab.offsetLeft + tab.offsetWidth > container.clientWidth - DROPDOWN_BTN_W(52)`.
  - 활성 탭 우선 정렬(`orderedTabs`) → 활성 탭은 항상 표시.
  - overflow 탭: `invisible pointer-events-none` (DOM 흐름 유지로 offsetLeft 측정 보장).
  - `>>` 버튼: `ChevronRight ×2 + 개수 + ChevronDown`, `absolute right-0` 고정.
  - 드롭다운 패널: `position: fixed` + `getBoundingClientRect()`로 부모 `overflow: hidden` 우회.
  - `ResizeObserver` 재계산, 외부 클릭/overflow 소멸 시 자동 닫기.
- **배포 전 검증:** 로컬 `npm run build`(`tsc -b && vite build`) 통과 확인 후 진행 (백색화면/TS 오류 사고 예방).
- **커밋/배포:** `f0f6238` 커밋 후 main push → GitHub Actions 자동 배포.

## 3. 결함 분석 및 수정: 핸들 동일성 비교 누락

사이드바에서 다른 폴더의 동명 파일이 동시에 active로 표시되는 결함 보고 → 분석 결과 **파일명(name)만으로 비교하는 동일 원인의 결함 2건** 확인.

### 결함 ① 사이드바 동명 파일 동시 active 표시 (보고 건)
- **위치:** `src/components/Sidebar.tsx:159`
- **원인:** `activeFileHandle?.name === entry.name` — 파일명 문자열만 비교(주석 `Simplified comparison`). 경로가 다른 동명 파일이 모두 `true`.
- **재현:** A폴더/AC.md + A폴더/B폴더/AC.md 구성에서 A/AC.md를 열면 사이드바의 A/AC.md, B/AC.md가 동시 하이라이트.

### 결함 ② 동명 파일 두 번째 열기 불가 (분석 중 추가 발견)
- **위치:** `src/App.tsx:190`
- **원인:** 중복 탭 판정 `tabs.find(t => t.handle?.name === handle.name && !t.isPdf)`도 이름만 비교. A/AC.md가 열린 상태에서 B/AC.md를 열면 새 탭이 안 열리고 기존 탭이 재활성화됨.
- **관계:** 보고된 재현절차(파일 1개만 열린 상태)에서는 트리거되지 않는 별개 단계의 결함이나, 뿌리는 동일한 "name-only 비교".

### 수정 내용 — `FileSystemHandle.isSameEntry()` 기반 핸들 동일성 비교
- **수정 방침:** 경로 문자열 매칭(tab.path 포맷 의존·null 위험) 대신 File System Access API의 표준 핸들 동일성 API 사용. 정확성·저침습.
- **결함 ① (`Sidebar.tsx`):** `isActive`를 `useState`+`useEffect`로 전환. 이름이 다르면 즉시 `false`(동기), **이름이 충돌할 때만** `isSameEntry`로 정밀 판정. `cancelled` 플래그로 race 방지. (import 변경 없음 → `noUnusedLocals` 위반 없음)
- **결함 ② (`App.tsx`):** `handleFileOpen`이 이미 async인 점 활용. 이름이 같은 후보에 한해 `await t.handle.isSameEntry(handle)`로 동일 파일 확인 후 중복 처리.
- **검증:** `tsc -b` 통과(exit 0).
- **수정→보고→승인→배포 순서 준수:** 분석·계획 보고 후 사용자 승인을 받아 수정, 별도 승인을 받아 배포.
