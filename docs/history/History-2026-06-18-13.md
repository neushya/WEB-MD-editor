## 1. 기능 추가: 다중 루트 폴더 워크스페이스 (LNB 폴더 추가/삭제)

### 요구사항
- **As-Is:** `폴더 열기` 시 단일 루트 폴더의 하위 트리만 LNB에 표시.
- **To-Be:** LNB에 여러 폴더를 추가/삭제 가능. 추가된 폴더는 폴더 열기와 동일 레벨(형제)로 표시.
  ```
  > 폴더1   (폴더 열기)
  > 폴더2   (폴더 추가)
  ```

### 설계 결정 (사용자 승인)
- **폴더 열기 = 교체(replace)** — 기존 동작 그대로 유지 (워크스페이스를 해당 폴더 단독으로 교체).
- **폴더 추가 = 추가(append)** — 기존 루트 목록에 형제로 추가 (VS Code "Add Folder to Workspace" 모델).
- **폴더 삭제** — 열기/추가 구분 없이 균일하게 제거.
  - LNB: 각 루트 헤더의 X 버튼으로 개별 삭제.
  - GNB: 파일 메뉴 "폴더 삭제" → 하위 메뉴로 현재 루트 목록 표시 후 선택 삭제.

### 구현 내용
- **`src/App.tsx`**
  - 상태 모델: `rootHandle`(단일) + `rootName` → **`roots: { id, handle }[]` 배열**로 전환.
  - 루트 id는 추가 시 생성(`Math.random().toString(36)`), 삭제는 **id 기준**. (이름·인덱스 key 사용 시 동명 폴더 충돌·인덱스 밀림으로 React 상태 손상 → id로 회피)
  - `handleFolderOpen`(교체), 신규 `handleAddFolder`(append + `isSameEntry` 중복 차단), `handleRemoveRoot`(id 제거).
  - **하위호환 마이그레이션**: 복원 시 기존 단일 핸들을 `Array.isArray(v) ? v : [v]`로 배열 승격(기존 사용자 폴더 유실 방지).
  - **영속화는 핸들러 내부 inline `set(WORKSPACE_KEY, ...)`** — 반응형 `useEffect([roots])`는 복원 전 빈 배열로 덮어써 데이터 유실되므로 회피(탭 저장의 `isInitialized` 가드와 동일 취지).
- **`src/components/Sidebar.tsx`**
  - `RootFolderNode` 컴포넌트 추출: 루트 1개당 자체 `entries`/`isRootOpen`/`isAuthorized` 상태 보유, 루트별 권한 체크·재인증.
  - Sidebar는 `roots` 배열을 형제로 map 렌더(각 `key={root.id}`).
  - 헤더에 **폴더 추가(FolderPlus)** 버튼 추가, 루트 헤더에 **X 삭제** 버튼.
  - 전역 새로고침: `refreshSignal`을 각 루트에 전달, 엔트리 래퍼에 `key={refreshSignal}`로 하위 트리까지 리마운트(펼친 폴더 변경분 반영).
  - `FileTreeItem`은 Part 12의 핸들 동일성 비교 로직 유지(변경 없음).
- **`src/components/GNB.tsx`**
  - 파일 메뉴에 "폴더 추가" 항목 + "폴더 삭제" 하위 메뉴(`submenu` 식별자) 추가.
  - 하위 메뉴: 현재 루트 목록을 우측 flyout으로 표시, 클릭 시 해당 루트 삭제. 루트 0개면 "열린 폴더 없음".

### 영향도 / 제약
- 모바일: 영향 없음(사이드바·폴더 기능 PC 전용, MobileLayout은 root 미참조).
- 탭/Editor/Preview: 영향 없음. 활성 파일 하이라이트는 다중 루트 간에도 `isSameEntry` 기반으로 정상.
- `handleReset`의 `del(WORKSPACE_KEY)` 그대로 동작.
- 제약: 복원된 폴더는 세션마다 권한 재허용 필요(루트 수만큼 프롬프트 가능), 중첩 폴더 추가는 허용(중복 트리 표시 가능), File System Access API 의존(Firefox 미지원).
- 의도된 동작: 루트 삭제해도 그 폴더에서 이미 연 탭은 닫히지 않음(탭 자체 핸들 보유, VS Code 방식).

## 2. advisor 검토로 보강한 결함 2건

- **A. 전역 새로고침이 펼쳐진 하위폴더 미갱신**: `RootFolderNode` 전환으로 루트 레벨만 reload되던 문제 → 엔트리 래퍼 `key={refreshSignal}`로 하위 트리 리마운트 복원(기존 parity).
- **B. GNB 하위 메뉴 1px 간격으로 메뉴 닫힘**: flyout의 `ml-px` 제거 → 항목과 flyout이 맞붙어 hover 이동 시 메뉴 유지.

## 3. 검증 (브라우저 실측)

- `npm run dev`(포트 3008) + Playwright + 실제 Chrome로 구동.
- ✅ 앱 로드 정상(백색화면 없음), **콘솔 에러 0건**.
- ✅ GNB 파일 메뉴에 폴더 열기/추가/삭제 표시.
- ✅ "폴더 삭제" hover → 우측 하위 메뉴 표시("열린 폴더 없음") + 부모 메뉴 유지(수정 B 검증).
- ✅ LNB 폴더 추가/열기 버튼 존재.
- ⚠️ **자동화 한계**: `showDirectoryPicker`는 네이티브 OS 다이얼로그라 Playwright 구동 불가 → 실제 폴더 추가/삭제, 영속성 왕복, 마이그레이션, 루트별 재인증, 중복 차단 alert은 **수동 확인 필요**(로직은 코드 반영 완료).
